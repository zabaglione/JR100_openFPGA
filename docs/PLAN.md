### P1-3 の実機確認手順

ROM ローダはまだ無いので、画面には**ブリングアップパターン**（オレンジの外枠 + 8色の
縦カラーバー + 1フレームに1ラインずつ下がる白いマーカー）が出る。これで
「スケーラがロックしたか」「アクティブ領域が 256×192 か」「垂直同期の周期が正しいか」
が同時に確認できる。

| 観測 | 意味 |
|---|---|
| カラーバーが出て、マーカーが滑らかに下降 | ✅ 62.4 Hz が通っている |
| 画面が出ない / エラー表示 | ❌ リフレッシュレートかタイミングが拒否された |
| 画像は出るがマーカーがカクつく・ちらつく | ⚠️ ロックはしているがフレーム落ちの可能性 |

## P1-3 実機デバッグ記録（2026-07-25）

JR-100 コアが `Load error in 'core' / General error / Error in core setup` で起動しない。

### 確定した事実

| 対象 | 結果 |
|---|---|
| **Arduboy**（agg23、配布 zip をそのまま展開） | ✅ **起動する**（`openFPGA Browse` が出る。`data.json` が HEX を `required: true` にしているため） |
| **Core Template**（Analogue 公式のビルド済み `.rbf_r`、手で組んだパッケージ） | ❌ 起動しない（※ icon.bin 追加・キャッシュ削除・クリーン eject **前**の結果。再テスト待ち） |
| **JR-100**（我々のビットストリーム） | ❌ 起動しない（上記の修正**後**も同じ） |

Arduboy が動く以上、**本体・SD カード・openFPGA 機能そのものは正常**。

### 環境

- SD: FAT32 / MBR / 31.3 GB / アロケーションブロック 32 KiB
- ファームウェア 2.6（`Analogue_Pocket.json` の runtime 2.6、build 2026-06-16）
- 両ビットストリームの SHA-256 はカード上で一致（転送は健全）

### 潰した仮説

| 仮説 | 判定 |
|---|---|
| `version_required: 2.2` とビットストリームの APF 世代（1.1）の不一致 | ❌ 1.1 に下げても変わらず。Arduboy も 1.1 |
| `System/` のキャッシュ破損 | ❌ 全ファイル非ゼロ。削除しても変わらず |
| SD の形式・容量・品質 | ❌ FAT32/MBR で公式サポート内。Arduboy は動く |
| macOS のゴミ（`._*` / `.Spotlight-V100`）、eject 忘れ | ❌ 一掃しても変わらず |
| `icon.bin` / `info.txt` の欠落 | ❌ 公式ドキュメントで optional。追加しても変わらず |
| **Pocket 側の初期化・開発者モード** | ❌ **そんなものは存在しない。** FW 1.1 以降 openFPGA は標準機能で、条件は SD が FAT32/exFAT であることだけ |

### 残る差分（Arduboy と比較して）

| 項目 | Arduboy（動く） | JR-100（動かない） |
|---|---|---|
| フォルダ名 = `author.shortname` | `agg23.Arduboy` 一致 | `zabaglione.JR100` に対し shortname が `JR-100` で**不一致だった** → 修正済み |
| `Platforms/_images/*.bin` | あり | **無かった** → プレースホルダ生成済み |
| `data_slots` | 1個（required） | 空 `[]` |
| scaler_modes | 800×720 | 256×192 |
| ビデオクロック | （不明、コア内でアップスケール） | **7.159 MHz**（低い） |
| リフレッシュ | 60 Hz 前後 | **62.4 Hz** |
| ビットストリーム | agg23 がビルド | 我々がビルド |

### 次の判定点

**Core Template を現在のカード状態で再テストする。**

- 動く → 原因は我々のビットストリーム。次はビデオ側（7.159 MHz / 62.4 Hz / 256×192）を疑い、
  テンプレートと同じ 320×240 @ 12.288 MHz を出す診断ビルドを作って切り分ける
- 動かない → 原因は手組みパッケージ側。Arduboy の配布 zip と1ファイルずつ突き合わせる

## 未解決の課題

| # | 課題 | 影響 | 対応方針 |
|---|---|---|---|
| 1 | 62.4 Hz が Pocket スケーラで通るか | **高** | P1-3 で実機検証。NG なら (a) 60Hz 付近へ調整（実機忠実性を犠牲）(b) フレームバッファ挿入 |
| 2 | ~~5CEBA4（18,480 ALM）に収まるか~~ | ~~中~~ | **解決。** P1-2 実測で 13% ALM / 5% BRAM。拡張 RAM と各ローダを繋いでも余裕がある |
| 3 | CMT ストリーミングのバッファ設計 | 中 | P6-2。bridge は数 MB/s と遅いので先読み量を確保する |
| 4 | Dock USB キーボードは非公式仕様 | 中 | 仮想キーボードを主、USB KB を副とする |

## 決定事項ログ

| 日付 | 決定 | 理由 |
|---|---|---|
| 2026-07-25 | 主参照を PocketCPC とする | MiSTer 8bit ホビーPC → Pocket の完動例。仮想KB / Dock USB KB / テープ / 書き戻しが揃っている |
| 2026-07-25 | `src/fpga/jr100/` は原則無改変 | 移植元のロックステップ検証結果を再利用するため |
| 2026-07-25 | `version_required` は 2.2 | 実機 FW は 2.6 だが、2.3 以降に本コアが必要とする機能追加は無い |
| 2026-07-25 | 外部メモリ（SDRAM/PSRAM/SRAM）は未使用 | JR-100 の全メモリは 42.25 KiB で BRAM に収まる |
| 2026-07-25 | **ビルドは GitHub Actions を主経路とする** | Apple Silicon 上のコンテナ実行は x86 エミュレーションで実用速度が出ない（MiSTer 版開発時の実測）。ローカルは最小確認用に残す |
| 2026-07-25 | ピクセルクロックは PLL 出力ではなくファブリック `/8` 分周で作る | `jr100_top` が内部で生成する `cen_pix` に位相を合わせる必要があり、PLL 出力では合わせられない。PocketCPC も同方式で実績がある |
| 2026-07-25 | ブリングアップ中も `vid_pixel` を映像経路に残す | パターンで上書きした初回ビルドで CPU・VIA・BRAM が丸ごとデッドコード除去され、435 ALM / 8 Kbit（空コアと同等）になった。合成が通っても中身が入っているとは限らない |
| 2026-07-25 | プラットフォーム画像（`_images/*.bin`）は P7 まで後回し | 521×165 / 2 バイトずつだが上位バイトが常に 0 で、PocketCPC 同梱の PNG と bin の内容が一致せず符号化を特定できなかった。装飾要素なので後段で扱う |
