### P1-3 の実機確認手順

ROM ローダはまだ無いので、画面には**ブリングアップパターン**（オレンジの外枠 + 8色の
縦カラーバー + 1フレームに1ラインずつ下がる白いマーカー）が出る。これで
「スケーラがロックしたか」「アクティブ領域が 256×192 か」「垂直同期の周期が正しいか」
が同時に確認できる。

| 観測 | 意味 |
|---|---|
| カラーバーが出て、マーカーが滑らかに下降 | ✅ 62.4 Hz が通っている |
| 画面が出ない / エラー表示 | ❌ リフレッシュレートかタイミングが拒否された |
| 画像は出るがマーカーがカクつく・ちらつく | ⚠️ ロックはしているがフレーム落ちの可能性 |

> **設計変更（2026-07-25）**: 当初計画の「HID → PS/2 変換 + `jr100_keyboard.sv` 流用」は取りやめ。
> `key_matrix[44:0]` はレベル信号なので、HID レポート（同時押し6キー＋修飾バイト）から
> 組み合わせ回路で直接デコードできる。PS/2 のイベント合成・エッジ追跡が丸ごと不要になる。
> PocketCPC が PS/2 を経由するのは輸入した CPC ロジックの都合であり、うちには当てはまらない。
> `jr100_keyboard.sv` は未使用となる（ファイルは参照用に残置）。
>
> 仮想キーボードの配列は実機の段組みを踏襲:
> `1-0` / `Q-P` / `A-;` / `Z-:` の4段（各10キー）+ `CTL SHFT SPC - RET`（幅広5キー）。
> 操作: Select 開閉、十字カーソル（リピート 300ms/70ms）、A=押下、B=SPACE、X=RETURN、
> L1=SHIFT ホールド、R1=CTL ホールド。開いている間はジョイスティックをマスク。

## P1-3 実機デバッグ記録（2026-07-25）

JR-100 コアが `Load error in 'core' / General error / Error in core setup` で起動しない。

### 確定した事実

| 対象 | 結果 |
|---|---|
| **Arduboy**（agg23、配布 zip をそのまま展開） | ✅ **起動する**（`openFPGA Browse` が出る。`data.json` が HEX を `required: true` にしているため） |
| **Core Template**（Analogue 公式のビルド済み `.rbf_r`、手で組んだパッケージ） | ❌ 起動しない（※ icon.bin 追加・キャッシュ削除・クリーン eject **前**の結果。再テスト待ち） |
| **JR-100**（我々のビットストリーム） | ❌ 起動しない（上記の修正**後**も同じ） |

Arduboy が動く以上、**本体・SD カード・openFPGA 機能そのものは正常**。

### 環境

- SD: FAT32 / MBR / 31.3 GB / アロケーションブロック 32 KiB
- ファームウェア 2.6（`Analogue_Pocket.json` の runtime 2.6、build 2026-06-16）
- 両ビットストリームの SHA-256 はカード上で一致（転送は健全）

### 潰した仮説

| 仮説 | 判定 |
|---|---|
| `version_required: 2.2` とビットストリームの APF 世代（1.1）の不一致 | ❌ 1.1 に下げても変わらず。Arduboy も 1.1 |
| `System/` のキャッシュ破損 | ❌ 全ファイル非ゼロ。削除しても変わらず |
| SD の形式・容量・品質 | ❌ FAT32/MBR で公式サポート内。Arduboy は動く |
| macOS のゴミ（`._*` / `.Spotlight-V100`）、eject 忘れ | ❌ 一掃しても変わらず |
| `icon.bin` / `info.txt` の欠落 | ❌ 公式ドキュメントで optional。追加しても変わらず |
| **Pocket 側の初期化・開発者モード** | ❌ **そんなものは存在しない。** FW 1.1 以降 openFPGA は標準機能で、条件は SD が FAT32/exFAT であることだけ |

### 続報（同日）

- **ロードエラーの原因確定**: コアフォルダ名は `core.json` の `author`.`shortname` と
  完全一致が必須（ドキュメントの "must be respected" は文字通り）。名前を一致させたら
  Core Template も JR-100 も起動するようになった
- **62.4 Hz はスケーラに受理される**: JR-100 コアが（内容は壊れているが）表示を出した
- しかしファブリック分周レジスタを `video_rgb_clock` にする構成は、位相を 3 通り
  （D+180°/D±0°/D−90°）試して全て失敗（白黒縞 → 真っ白 → グレー）
- `apf_top.v` を精読して構造が判明: `video_rgb_clock` は **DDIO セルの outclock**
  （RGB 24bit を 12bit DDR に直列化）、`video_rgb_clock_90` はスケーラのクロックピンを
  生成する別 DDIO を駆動する。ファブリックレジスタをこの用途に使うのは PocketCPC が
  綿密な SDC 調整込みで成立させている非自明な構成だった

### 採った解決策（アーキテクチャ変更）

出力段を**実機で動作確認済みのテンプレート構成そのまま**に載せ替えた:

- 第2 PLL で 12.288 MHz の 0°/90° 実クロック対を生成（mf_pllbase と同一パラメータ、20345 ps シフト）
- スキャンは 320×240 active / 400×512 total = **60.0 Hz ちょうど**
- JR-100 の実機準拠ラスタ（7.159 MHz / 62.4 Hz / NTSC 非準拠同期）は機械の内部に完全に閉じ、
  **1bpp デュアルクロックフレームバッファ（48 Kbit、BRAM の 1.5%）**で橋渡し
- 書き手 62.4 Hz と読み手 60.0 Hz はフリーラン。動画ではティアラインが出得るが、
  テキスト主体の JR-100 では実用上問題ない。必要ならダブルバッファで解消可能（P7 で判断）
- モノクロ 1bpp だからこの橋が安価に成立する（これが JR-100 の仕様に即した設計）
