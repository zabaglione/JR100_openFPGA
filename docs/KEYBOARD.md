# JR-100 キーボード資料

仮想キーボードのラベルと HID マッピングの根拠。

## 一次資料

1. **実機キーボード図**（JR-100 技術資料。2026-07-25 にユーザー提供）
   - マトリクス: KEYSEL 0-8（VIA ポート A bit3-0 で選択、$C801）× D4-D0（ポート B bit4-0、$C800 で読む。0=押下）
   - 各キーキャップに最大 4 面の刻印: 通常（左下）/ SHIFT（右上）/ GRAPH（左上）/ GRAPH+SHIFT（右下）
2. **BASIC ROM のキー変換テーブル**（boot.rom 内、実動作の根拠）
   - 通常面: `0x1A6C`（43 バイト、Z X C / A-G / Q-T / 1-5 / 6-0 / Y-P / H-; / V-, / . SP : CR - の順）
   - シフト面: `0x1A99`（同順）
3. **キャラクタジェネレータ**（boot.rom `0x0000-0x03FF`、128 グリフ × 8 バイト）
   - 表示コード = ASCII − 0x20（例: 'A'=0x21、'@'=0x20）
   - ASCII '\\' の位置（表示 0x3C）は **¥**
   - 表示 0x40-0x7F はピクトグラム/セミグラフィックス（0x41-0x44 にトランプの ♠♥♦♣、0x46-0x49 に ←↓↑→ など）

※ **要実機確認**: キーボード図の刻印は `9(` `8)` だが、ROM テーブルの読みでは
`8(` `9)`。仮想キーボードのラベルは実動作（ROM）に合わせる方針。
SHIFT+8 の実機出力で決着させる。

## GRAPH モード（2026-07-25、参照エミュレータで全キー実測済み）

測定方法: pyjr100emu を Python API から駆動し、各キーを 4 状態
（通常 / SHIFT / GRAPH / GRAPH+SHIFT）で押して VRAM のカーソル位置の
表示コードを読む（scratchpad の graph_map2.py 方式）。

### 確定した規則

1. **GRAPH は「出るはずのコードの bit6 を立てる」だけ**
   - 通常面・シフト面のコードに `| 0x40`。全 41 キーで例外なし
   - 例: `A` 0x21→0x61、`1` 0x11→0x51、SHIFT+`1` 0x01→0x41（=♠）
2. **GRAPH+SHIFT+数字 1-4 = トランプ記号** ♠(0x41) ♥(0x42) ♦(0x43) ♣(0x44)
3. **SHIFT で無反応のキーは GRAPH+SHIFT でも無反応**
4. **解除条件**: RETURN（エラー行・空行どちらでも）、およびリセット。
   CTRL+V は純粋なトグル

### FPGA 側の追跡（2026-07-25 改訂: バススヌープ方式）

当初はマトリクス監視（CTL+V トグル / RETURN クリア）で推測していたが、
**ROM がキーを処理しなかった場合にずれる不具合が実機で発覚**（例: 表示は解除、
ROM は GRAPH のまま）。

現方式: ROM は GRAPH 状態をワーク RAM **`0x0014`**（0x00=通常、0x10=GRAPH）に
保持している（参照エミュレータで CTRL+V 前後の RAM 差分により特定。候補は
この 1 バイトのみで、RETURN クリアとも整合）。`jr100_top` に受動バスタップ
（`dbg_bus_*`、PROVENANCE.md 記録）を追加し、core_top が `0x0014` への CPU 書き込みを
スヌープして実状態をそのまま表示に使う。**推測が入らないため、ROM が無視した
キー・プログラムからの POKE も含めて絶対にずれない。**

### ラベル描画

オーバーレイは boot.rom ロード時のストリームから**キャラクタ ROM の影コピー**
（1 KiB デュアルクロック BRAM）を作り、実機グリフそのものでラベルを描く。
GRAPH 面は `コード | 0x40` を引くだけで、トランプ記号もセミグラも
ピクセル完全一致で表示される。手描きフォントは廃止。

## Dock USB キーボード

HID usage → マトリクス位置の直接デコード（`jr100_pocket_input.sv`）。
記号は**物理配置ベース**: JR-100 に無い記号キーは無視され、@ は実機同様
SHIFT+U で入力する。
